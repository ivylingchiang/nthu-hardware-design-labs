Jaccard Similarity

The Jaccard Similarity, also called the Jaccard Index or Intersection over Union (IoU), is a statistical measure used to compare the similarity and diversity of sample sets. It quantifies how similar two finite sets are by comparing their intersection to their union.

Key facts

  • Formula: |A ∩ B| / |A ∪ B|
  • Range: 0 (no overlap) to 1 (identical sets)
  • Invented by: Paul Jaccard, 1901
  • Applications: Data mining, natural language processing, image analysis

Definition and calculation

Jaccard Similarity is defined as the size of the intersection divided by the size of the union of two sets. Mathematically,

J(A, B) = |A ∩ B| / |A ∪ B|.

If both sets are empty, the similarity is often defined as 1 by convention. It captures the proportion of shared elements relative to the total distinct elements across both sets.

Uses in data science and machine learning

This metric is widely used for comparing binary attributes or categorical data, such as text documents, user preference sets, and image segmentation masks. In clustering and classification, it serves as a measure of pairwise similarity for items represented as sets or binary vectors. The complement, Jaccard distance (1 − Jaccard similarity), is frequently used in distance-based algorithms like k-means and hierarchical clustering.

Relation to other similarity measures

While similar to the Cosine Similarity, Jaccard Similarity focuses on set membership rather than vector magnitude. It is more appropriate for sparse, discrete data where only presence or absence of features matters, whereas cosine similarity accounts for frequency or intensity of features.

FAISS

FAISS (Facebook AI Similarity Search) is an open-source software library developed by Meta AI for efficient similarity search and clustering of dense vectors. It enables fast nearest-neighbor retrieval across very large datasets, supporting both CPU and GPU acceleration. FAISS is widely used in machine learning and information retrieval applications.

Key facts

  • Developer: Meta AI (formerly Facebook AI Research)
  • Initial release: 2017
  • Primary language: C++ with Python bindings
  • Core purpose: High-dimensional vector similarity search
  • License: MIT License

Architecture and Functionality

FAISS provides a suite of algorithms and data structures optimized for large-scale vector search. It supports exact and approximate nearest neighbor (ANN) methods, using quantization and indexing techniques to balance speed and accuracy. Its modular design allows flexible choice of index types such as flat, IVF (inverted file), HNSW (hierarchical navigable small world), and PQ (product quantization).

GPU and Performance Optimization

A key advantage of FAISS is its support for GPU acceleration, enabling search operations across billions of vectors in milliseconds. The library implements CUDA-optimized kernels and provides multi-GPU and distributed search capabilities. These optimizations make FAISS suitable for large-scale deployment in recommendation systems, semantic search, and embedding retrieval.

Applications and Ecosystem

FAISS underpins many real-world machine learning pipelines, particularly for tasks requiring similarity-based retrieval—such as image or text embedding search, clustering, and deduplication. It integrates with frameworks like PyTorch and is often paired with vector databases and AI platforms to provide scalable vector indexing infrastructure.

Development and Community

Since its release, FAISS has been actively maintained by Meta and open-source contributors. Its extensive documentation, tutorials, and benchmarks have established it as a de facto standard in the vector similarity search domain. The project continues to evolve with support for new index types and performance improvements.

總結

現在訓練 LLM 的資料去重面臨一個極端的兩難：要嘛用極度便宜但只能抓「逐字抄襲」的 MinHash；要嘛用能抓出「換句話說 (改寫)」但貴到無法在大規模資料上運作的 SemDeDup (Transformer 模型)。

這個研究的核心點子是：借鏡資料庫（如 LSM-Tree）的分層過濾 (Filter-and-Verify Cascade) 設計。先用便宜的技術（如 Static Embedding 或 MinHash）以極低的成本過濾掉 90% 「明顯不重複」或「完全一模一樣」的資料，只把剩下 10% 處於「模糊地帶」的資料，送交給昂貴的 Transformer 模型做最終判定。

關鍵技術

  1. MinHash (Min-wise Independent Permutations)
    1. 概念：一種用來快速估算兩個集合相似度（Jaccard Similarity）的降維技術。
    1. 原理：

      將文章切成多個 N-gram (Shingles)，通過多個 Hash 函數映射，只保留每個 Hash 的最小值組成 Signature。
      比較 Signature 相同的比例，就能推算出原文的重疊度。

    1. 限制：

      它是基於字面 (Syntactic) 的比對。如果一句話從「這是一隻可愛的狗」改成「這隻小狗長得很討喜」，字面重疊極低，MinHash 就會判定為不重複。

  1. SemDeDup (Semantic Deduplication)
    1. 概念：基於語意理解的去重。
    1. 原理：

      利用 Transformer（如 Sentence-Transformers）將文章轉化為高維度向量 (Dense Embedding)。
      在向量空間中，如果兩個點的 Cosine Similarity 很高（例如 > 0.9），就代表語意相似。
      為了避免 O(N2) 的全域兩兩比對，通常會先用 K-Means 進行聚類 (Clustering)，只在同一個 Cluster 內做比對。

  1. Static Embedding (如 Model2Vec)
    1. 概念：Transformer 的「輕量化平替」。
    1. 原理：

      傳統 Transformer 會根據上下文動態計算每個字的向量（Attention 機制），計算量巨大。Model2Vec 這類技術則是把 Transformer 的知識「蒸餾」成一個固定的靜態詞典（類似傳統的 Word2Vec）。查詢時只需把句子中每個字的向量查表並加總（或平均），省去了極度耗時的矩陣運算，速度可提升百倍以上。

重點筆記

核心假設：語意相似度的「雙峰分佈 (Bimodal Distribution)」

重點：

這是整個 Cascade 架構能否成功的生死關鍵。如果多數資料的相似度都落在 0.7 - 0.95 的「模糊地帶」，那分層過濾就沒有意義，因為多數資料最終還是得送進 Transformer。只有當資料呈現兩極化（絕大多數毫不相干，少數完全重複），這個架構才能發揮巨大的 Cost-saving 效益。

跨界思維：將 LSM-Tree 最佳化引入 LLM Pipeline

重點：

LSM-Tree 中的 Bloom Filter 是為了減少不必要的 Disk I/O；而這裡的「便宜模型」是為了減少不必要的 GPU Compute (Transformer)。

補充說明：

如同 Monkey 論文中對 False Positive Rate (FPR) 的最佳化分配，這個去重架構可以建立一個成本數學模型：

E[Cost]=Costcheap​+P(Escalate)×Costexpensive​

系統工程師的目標，就是透過調整 Threshold，在保證召回率 (Recall) 的前提下，最小化整體的 Expected Cost。

系統瓶頸的轉移：從 Compute Bound 到 I/O Bound

重點：

目前的去重工具多採用 Batch 處理（讀取 → 處理 → 寫入 Parquet → 下一階段再讀取）。當算力成本被 Static Embedding 壓低後，Pipeline 的瓶頸將立刻轉移到 Storage I/O 上。

補充說明 (架構優化)：

如果能將多層級去重改寫為 Streaming Pipeline，利用 In-memory 資料傳遞（如 Apache Arrow），或者在底層採用更高效的 I/O 堆疊（例如繞過 Kernel 的 Zero-copy 機制或 io_uring 非同步 I/O 讀取原始語料），可以大幅減少 Intermediate 檔案落地的開銷，這會是工程實作上一個極大的亮點。

核心問題

1. 現有的去重方法到底怎麼運作？

MinHash 估算 Jaccard：

透過計算兩篇文章 N-gram 集合的交集除以聯集。它只能抓 Syntactic 重複是因為它把文章視為「字串的集合」，無法理解詞彙背後的關聯（如「開心」與「快樂」對它來說是完全不同的字串）。

SemDeDup 運作：

使用如 all-mpnet-base-v2 等模型提取特徵。為了避免兩兩比對爆炸，它先對整個 Corpus 進行 K-Means 分群，然後只計算同群內文件對的 Cosine Similarity，超過設定的 Threshold（如 0.8）就刪除。

Static vs. Transformer：

Static Embedding（如 Model2Vec）沒有 Attention 機制，無法處理一詞多義或複雜語境，因此在「模糊地帶」的精準度會斷崖式下降。但它快在只需「查表 + 矩陣相加」，沒有龐大的線性層運算。

2. 語意相似度的分佈長什麼樣？

根據 SemDeDup (Abbas et al., 2023) 的觀察，網頁文本（如 C4）的相似度分佈並非完全的雙峰，而是呈現「右尾極長」的偏態分佈。絕大多數的文件對相似度低於 0.3，而在 0.8 以上會有一個微小的隆起（代表改寫或抄襲的網頁）。

領域差異：

Code Corpus (如 The Stack) 的分佈會更偏向高相似度，因為程式碼有大量的樣板 (Boilerplate) 和重複的開源授權聲明；Scientific Text 則會在特定的專業術語上有較高的 Baseline 重疊。

3. 便宜的近似方法在「模糊地帶」的可靠性如何？

在 Cosine 0.7 - 0.95 這個區間，Static Embedding 的可靠度會顯著下降。因為這個區間通常包含大量「句型結構不同但語意一致」的改寫，Static Embedding 缺乏全局 Attention，容易將它們誤判為低相似度（False Negative）。

策略：這正是 Cascade 架構存在的理由。便宜模型不需要在模糊地帶很準，它只需要能極度精準地判斷出「絕對不相似 (< 0.7)」的 case 並把它們剔除即可。

4. Filter-and-verify cascade 的 Cost Model 怎麼建？

參數：

你需要定義 C1​ (第一層處理單篇文件的時間/算力成本)、C2​ (第二層成本)、TL​ (直接丟棄的下限閾值)、TH​ (直接判定重複的上限閾值)，以及 P(Escalate) (落在 TL​ 到 TH​ 之間的機率)。

借鏡 Monkey：

Monkey 是在給定記憶體下最小化 I/O；在這裡，你是在給定的去重品質（以完整的 SemDeDup 輸出為 Ground Truth，計算 F1-score）下，尋找最佳的 TL​ 和 TH​ 以最小化整體 Compute Cost。

Pipeline 的 I/O 行為可以怎麼改善？

現狀：

HuggingFace datasets 配合 text-dedup 往往會在每個階段產生大量的 .arrow 或 .parquet 快取檔案落地。

改善：

將階段一（MinHash / Static Embedding）和階段二（Transformer Verify）整合在同一個進程的 Generator 中。當第一階段發現一個疑似 Pair 時，不要寫入磁碟，直接透過記憶體中的 Queue 傳遞給駐留在 GPU 中的 Transformer 模型進行即時驗證。這不僅省下磁碟寫入，更能大幅減少重複序列化/反序列化 (Serialization) 的 CPU 負擔。

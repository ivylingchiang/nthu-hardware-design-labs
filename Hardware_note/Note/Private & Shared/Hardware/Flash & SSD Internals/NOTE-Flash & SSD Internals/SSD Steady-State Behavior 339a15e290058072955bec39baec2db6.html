SSD Steady-State Behavior

SSD Steady-State Behavior

YouTube 開箱影片裡，評測者拿到一顆全新的 NVMe SSD，打開 CrystalDiskMark，跑出 sequential read 7,000 MB/s 的成績，彈幕一片「好猛」。但如果你把同一顆 SSD 拿來當 OS 碟用了半年，每天承受系統 log、瀏覽器 cache、各種應用程式的零碎寫入，再跑一次同樣的 benchmark，數字會不太一樣。

差距不是因為 SSD 壞了，而是因為第一次測的是 fresh state，第二次面對的是 steady state，這是兩個完全不同的運作條件。只看開箱成績就下單的 SSD 評測，跟只看入學成績不看畢業率的大學排名一樣，只說了故事的前半段。

Key Word Definition/ Discussion
Steady state vs fresh state

Fresh state: SSD 剛開始使用時的狀態，所有 NAND block 幾乎都是空的（erased）。

Steady state: SSD 經過長時間使用後，進入GC 持續發生、效能穩定但較低的狀態。

Fresh state 的特徵：

  • NAND flash 上所有 block 都是 erased 的（空白的）
  • 每次寫入都直接找一個空白 page，零 GC 開銷
  • Write amplification 接近 1（幾乎沒有額外寫入）
  • 寫入延遲非常穩定，幾乎看不到 tail latency spike
  • 規格表（spec）通常測的是這個狀態
  • 幾乎不會出現在真實長期運行系統中

Steady state 的特徵：

  • NAND flash 上大部分 block 都已經被寫過
  • 每次寫入都可能觸發 GC 來回收空間
  • WAF 明顯大於 1（典型值 2-5，取決於 workload 和 OP）
  • 寫入延遲出現顯著的 tail latency spike（p99 延遲可能是 p50 的 10-100 倍）
  • steady state throughput ≈ fresh 的 30–50%
  • 真實系統（DB / server）幾乎都在這個狀態
  • 設計系統時應以這個為準

Transition

從 fresh state 過渡到 steady state 的過程很簡單：

持續寫入資料，直到 SSD 第一次耗盡所有空白 block、開始觸發 GC。對於消費級 SSD（7% OP），這大約是寫滿 SSD 容量一次之後就會開始進入 steady state。對於企業級 SSD（28% OP），可能需要寫滿 1-2 次。

一個常被忽略的事實是：steady state 的效能可能只有 fresh state 的 30-50%。也就是說，規格表上 500K IOPS 的 SSD，在 steady state 下可能只剩 150-250K IOPS。這不是 SSD 壞了，這是正常行為。

Tail latency

延遲分佈中「最慢的那一段」

為什麼 steady state 的效能會下降？

根本原因是 GC 和使用者的 I/O 請求在競爭 NAND flash 的頻寬。

NAND flash 的 die/plane 在任何時刻只能做一件事：要嘛服務使用者的讀寫請求，要嘛執行 GC 的資料搬移和 block erase。當 GC 正在搬移 valid page 時，使用者的寫入請求必須等待（或者被路由到其他 die，如果有空閒的話）。

GC ↑ → user I/O ↓

平均 throughput 下降：

假設 NAND flash 的總頻寬是 2 GB/s。如果 GC 需要消耗其中 40% 的頻寬來搬移 valid page 和做 block erase，那使用者實際可用的頻寬只剩 1.2 GB/s。WAF 越高，GC 消耗的頻寬比例越大，使用者可用的頻寬越少。

WAF ↑ → GC 頻寬消耗 ↑

Tail latency spike：

更大的問題不是平均值下降，而是延遲的「不可預測性」。GC 操作是 bursty 的：有時候 SSD 有足夠的 free block，GC 不需要工作，延遲很低；有時候 free block 快耗盡，GC 緊急介入，一口氣要搬移大量資料，期間使用者的 I/O 全部被阻塞。

GC 是 bursty

  • 平常：低延遲
  • 緊急 GC：大量搬資料 → I/O 被 block

在一些對延遲敏感的應用場景（例如資料庫的 transaction processing），p99 latency 比 average latency 更重要。一個平均延遲 0.1 ms 但 p99 延遲 50 ms 的 SSD，在這些場景下可能不如一個平均延遲 0.2 ms 但 p99 延遲 2 ms 的 SSD。

SSD 韌體可以用一些策略來緩解 tail latency：

  • Background GC：

    在 SSD idle 的時候主動做 GC，預先回收空間。但如果 workload 持續不停，idle 時間很少，background GC 幫助有限。

  • GC pacing：

    限制 GC 的頻寬佔比，避免 GC 一次性佔用太多資源。但這可能導致 free block 耗盡的情況更容易發生。

  • Multi-stream write：

    讓 host 端告知 SSD 資料的冷熱屬性，SSD 把冷熱資料分開放在不同 block 中，提高 GC 效率。

Over-provisioning → Steady state

Over-provisioning（OP）比例是影響 steady state 效能最直接的因素。

用一組具體數字來說明。假設一顆 SSD 有 1,024 GB 的 NAND flash：

標示容量OP 比例OP 空間Steady state WAFSteady state throughput（相對）
960 GB7%64 GB~3-5低
800 GB28%224 GB~1.5-2中
640 GB60%384 GB~1.1-1.3高

OP 比例從 7% 提高到 28%，WAF 可以降低一半以上，steady state throughput 明顯提升。但代價是使用者可用容量從 960 GB 減少到 800 GB。

為什麼 OP 能這麼有效？因為更多的 OP 代表：

  1. 任何時刻都有更多 free block 可用，GC 不需要在空間緊迫時才啟動
  1. GC 有更多選擇，可以挑選 invalid page 比例高的 block 來回收，搬移的 valid page 更少
  1. GC 的啟動頻率更低，與 user I/O 的競爭更少

這也解釋了為什麼企業級 SSD 通常提供多種容量版本（例如 800 GB、1.6 TB、3.2 TB）但使用相同的 NAND flash 總量。800 GB 版本有更多 OP，效能和壽命都更好，適合 write-intensive workload；3.2 TB 版本 OP 較少，適合 read-intensive workload。

GC interference → Steady state

GC 與 user I/O 同時競爭 NAND 資源，導致效能下降與延遲增加。

  • GC 需要：
    • read valid page
    • write 到新 block
    • erase 舊 block

這些操作和 user write 用同一資源

  • 本質 = resource contention
  • 和 CPU context switching 很像

Benchmarking methodology

理解了 fresh state 和 steady state 的差異後，最重要的實務意義就是：SSD 的效能測試必須在 steady state 下進行，否則結果沒有參考價值。

正確的 benchmarking 流程

Step 1: Preconditioning（預處理）

在正式測量前，先用與實際 workload 類似的 I/O pattern 對 SSD 進行持續寫入，直到效能指標穩定下來。「穩定」的判斷標準通常是：連續多個測量週期（例如每個週期 1 分鐘）的 throughput 或 IOPS 變異係數（coefficient of variation）低於某個閾值（例如 10%）。

對於 random write 測試，preconditioning 通常需要：

  • 先用 sequential write 填滿整顆 SSD 兩次（確保所有 block 都被寫過）
  • 再用目標 random write pattern 持續寫入，直到效能穩定

整個 preconditioning 可能需要數小時甚至一天。

Step 2: Steady-state measurement（穩態測量）

Preconditioning 完成後，開始正式的效能測量。測量時間要足夠長，覆蓋多個 GC cycle，才能準確反映 GC 對效能的影響。通常建議至少測量 30 分鐘到 1 小時。

Step 3: 記錄完整的延遲分佈

只報告 average throughput 或 average latency 是不夠的。必須記錄完整的延遲分佈，包括 p50、p90、p95、p99、p99.9、p99.99 甚至 max latency。因為 GC 造成的 tail latency spike 只會出現在高百分位數，average 值會完全掩蓋這個問題。

很多 SSD review 網站和廠商的規格表只報告 fresh state 下的數字。下次你看到論壇上有人說「我這顆 SSD 跑分比你快」，先問一個問題：他測的是剛開箱的成績，還是用了三個月之後的成績？身為系統設計者，你需要知道這些數字在 steady state 下可能縮水 50% 以上。如果你在設計一個 latency-sensitive 的系統，你必須用 steady state 下的 p99 甚至 p99.9 latency 來做 capacity planning，而不是用 fresh state 的 average latency。

Key Concepts
理解 fresh state 與 steady state 的差異：fresh state 下所有 block 都是乾淨的，效能表現無法代表真實使用情境

Answer

Fresh state（全新狀態）時 SSD 充滿空白區塊，寫入時不需額外清理；Steady state（穩定狀態）則是空間寫滿後，寫入前必須先進行垃圾回收（GC），這才是真實環境長久運作後的效能。

Key Concept

  • Fresh State: 只有單純的寫入動作 (Write)，沒有背景干擾。
  • Steady State: 寫入動作必須伴隨讀取、搬移與抹除 (Read-Modify-Write / Erase)，寫入放大 (WAF) 增加。

Detail

當 SSD 剛開箱 (Fresh Out of the Box, FOB) 時，NAND Flash 內所有的 Block 都是處於已抹除 (Erased) 的乾淨狀態。此時控制器收到主機的寫入請求，可以直接將資料寫入空白的 Page 中，速度極快。然而，隨著硬碟被寫滿，SSD 必須開始回收包含無效資料 (Invalid pages) 的 Block。在 Steady state 下，每一次的主機寫入都可能觸發底層的 Garbage Collection (GC)，導致系統必須先將有效資料搬移到新 Block，然後抹除舊 Block，最後才能寫入新資料。這個過程會大幅消耗底層頻寬，使得效能顯著下降並趨於平穩，這才是評估 SSD 在生產環境中真實表現的唯一指標。

了解在 steady state 下 GC 會與使用者 I/O 競爭 NAND flash 頻寬，導致 tail latency 出現明顯的 spike

Answer

Garbage Collection 需要在 NAND 晶片內部進行資料的讀取、寫入與區塊抹除，這些操作會佔用匯流排與晶片資源，迫使同時發生的使用者 I/O 請求必須排隊等待，導致延遲瞬間飆高 (Spike)。

Key Concept

  • 資源競爭: GC 的內部操作與主機端的外部 I/O 共享同一條通道與 Die 資源。
  • 抹除延遲 (Erase Latency): NAND Flash 的 Block Erase 操作極度耗時（通常達數毫秒），在此期間該 Die 無法服務任何讀寫請求。

Detail

在 SSD 內部，GC 是一個極度耗費資源的過程。當 GC 啟動時，SSD 控制器必須發送指令到 NAND Flash 執行讀取（找出現存的 Valid pages）、寫入（搬移到新 Block）以及抹除（清空舊 Block）。特別是「抹除」動作，其物理延遲遠高於讀寫。如果使用者的 I/O 請求剛好被分配到正在執行 GC 或 Erase 操作的 NAND Die 上，該請求就必須在佇列中等待操作完成。這種硬體層級的阻塞現象 (Blocking) 反映在應用程式端，就是平時原本只有微秒級的延遲，偶爾會突波 (Spike) 到數十毫秒，形成嚴重的 Tail Latency (如 P99 或 P99.9 延遲)。

理解 over-provisioning 比例如何影響 steady state 的效能：OP 越高，GC 的負擔越輕，tail latency 越穩定

Answer

Over-provisioning (OP) 提供了隱藏的備用空間，讓控制器有更多餘裕尋找「無效資料最多」的區塊來進行回收，大幅減少需要搬移的有效資料量，從而提升效能並穩定延遲。

Key Concept

  • 降低寫入放大 (WAF): OP 越大，GC 需要搬移的 Valid Pages 越少。
  • 提升吞吐量與穩定性: 減少內部資料搬移，代表保留更多可用頻寬給主機 I/O。

Detail

Over-provisioning 是 SSD 總物理容量與使用者可用容量之間的差值。在 Steady state 下，控制器在進行 GC 時，會使用貪婪演算法 (Greedy Algorithm) 優先挑選 Invalid pages 比例最高的 Block 來抹除。如果 OP 只有 7%，SSD 處於擁擠狀態，每個 Block 可能都塞滿了 Valid pages，導致 GC 必須搬移大量資料才能清出一個 Block。反之，如果 OP 高達 28%，SSD 隨時保有大量備用空間，控制器可以輕易找到幾乎全是無效資料的 Block 進行抹除，幾乎不需要搬移有效資料。這不僅顯著降低了寫入放大因子 (WAF)，也解除了 GC 對系統頻寬的佔用，使 IOPS 維持高檔，Tail Latency 也能保持穩定。

知道正確的 SSD benchmarking methodology 需要先進行 precondition 讓 SSD 進入 steady state，才能反映真實效能

Answer

正確的測試必須先透過大量且持續的寫入（Preconditioning）耗盡 SSD 的空白區塊，強迫其進入必須一邊 GC 一邊寫入的 Steady state，這樣測得的數據才具有伺服器佈署的參考價值。

Key Concept

  • 排除快取干擾: 填滿 DRAM 快取與 SLC Cache。
  • 強迫觸發 GC: 將所有實體空間寫滿，讓 WAF 達到穩定的最大值。

Detail

企業級儲存 SNIA (Storage Networking Industry Association) 規範了嚴格的測試標準。如果只對剛開箱的 SSD 跑十分鐘的測試，你測到的只是「DRAM 速度」或是「SLC Cache 的爆發速度」，完全沒有觸發 GC。正確的流程 (Preconditioning) 通常包含：先完整抹除整顆磁碟 (Secure Erase)，接著以連續寫入 (Sequential Write) 填滿 2 倍以上的磁碟容量，最後再套用目標的隨機讀寫負載 (Random Workload) 持續數小時，直到效能曲線呈現水平的直線（變化率極小）。只有在這個平台上取得的 IOPS 與 Latency 數據，才能保證 SSD 在未來上線運作三年後，依然能維持這個水準。

Test your understanding
一顆消費級 SSD（7% OP）和一顆企業級 SSD（28% OP）使用相同的 NAND flash。在 fresh state 下它們的 sequential write 效能幾乎相同。為什麼在 steady state 下企業級 SSD 的效能明顯優於消費級？

Answer

因為 28% OP 的企業級 SSD 在穩態下擁有更多備用空間，使 Garbage Collection 能以更低的成本（搬移更少的有效資料）清出可用區塊，寫入放大 (WAF) 較低，從而保留更多內部頻寬給主機。

Key Concept

  • OP 比例直接決定了 Steady State 下的 GC 效率。
  • Fresh state 下不需要 GC，因此兩者發揮的是相同的 NAND 物理極限頻寬。

Detail

在 Fresh state 下，兩顆 SSD 都是直接將資料寫入空白的 NAND Page，完全不需要進行 GC，因此效能瓶頸在於 NAND Flash 顆粒本身的物理寫入速度與通道數，兩者硬體相同，效能自然一致。然而進入 Steady state 後，SSD 必須先清出空間才能寫入。7% OP 的消費級 SSD 因為空間緊湊，GC 時必須把大量有效的資料搬來搬去（WAF 極高），這消耗了 NAND 絕大部分的 I/O 頻寬。而 28% OP 的企業級 SSD 隨時都有四分之一以上的閒置與無效空間，GC 可以輕易找到充滿垃圾資料的 Block 直接抹除。企業級 SSD 花在內部整理的力氣小，自然有更多力氣處理外部主機的寫入請求。

為什麼只看 average latency 不足以評估 SSD 在生產環境的表現？請用一個具體的應用場景（例如 OLTP 資料庫）說明 tail latency spike 會造成什麼實際問題。

Answer

Average latency 會將極少數極端緩慢的 I/O 請求平均掉，掩蓋了效能卡頓的真相。
在 OLTP 等系統中，一個高延遲突波 (Tail latency spike) 就會卡住整個交易流程，導致嚴重的用戶體驗下降。

Key Concept

  • 長尾效應 (Tail Latency): P99 或 P99.9 代表最慢的 1% 或 0.1% 的請求。
  • 同步依賴: 資料庫的 ACID 特性要求寫入必須落盤才能繼續下一步。

Detail

假設一顆 SSD 的平均延遲是 0.5ms，看起來非常優異，但其 P99.9 延遲可能高達 50ms（這是因為遇到了 GC 抹除 Block 的阻塞）。
在 OLTP (線上交易處理) 資料庫中，使用者的每一次購買或轉帳通常涉及數十個平行的 I/O 請求，且為了保證資料一致性，必須等待最慢的那一個 I/O 完成後才能 Commit。
如果系統每秒處理數千個交易，P99.9 的 50ms 延遲會頻繁地成為交易的瓶頸 (Bottleneck)，導致資料庫連線池佔滿、應用程式 Timeout、甚至引發微服務架構中的連鎖效應 (Cascading failure)，這些都是單看 "Average latency" 完全無法預測的災難。

描述一個完整的 SSD steady-state benchmarking 流程。為什麼 preconditioning 階段需要先 sequential write 填滿 SSD 再切換到目標 workload pattern？

Answer

流程：Secure Erase -> Sequential Fill (2x 容量) -> Random Workload Preconditioning -> 測量與驗證。先用 Sequential fill 是為了確保邏輯區塊位址 (LBA) 全面映射到實體區塊，打破控制器資料壓縮或簡化處理的捷徑。

Key Concept

  • SNIA 標準流程: 確保測試的一致性與可重複性。
  • Sequential Fill 的目的: 建立完整的 LBA 到 PBA 映射表 (Mapping Table)，消除 FOB 狀態。

Detail

一個符合工業標準的 SSD Benchmarking 流程如下：

  1. Purge (淨化): 下達 NVMe Format 或 Secure Erase 指令，清空 Mapping table。
  1. Workload Independent Preconditioning: 以 128KB 循序寫入將硬碟總容量寫滿至少兩次。這一步非常關鍵，它迫使 FTL (Flash Translation Layer) 為所有 LBA 分配實體 NAND 空間，確保沒有任何 "未分配" 的捷徑可走，同時也確保後續的隨機寫入必定會觸發 GC。
  1. Workload Specific Preconditioning: 切換到你要測試的負載（例如 4KB 隨機寫入），持續運行並監控 IOPS，直到效能數據在一個區間內呈現收斂（通常認定連續幾個時間窗口的變異數極小，即視為進入 Steady State）。
  1. Measurement (測量): 在確認進入 Steady State 後，才開始記錄接下來的 IOPS 與 Latency 數據。

一顆 SSD 在 fresh state 下的 random write IOPS 是 400K，steady state 下降到 150K。請推算 GC 大約消耗了多少比例的 NAND flash 頻寬。

Answer

GC 大約消耗了 62.5% 的 NAND Flash 頻寬。

Key Concept

  • Fresh state (400K) 代表 NAND Flash 後端的 100% 原始處理能力。
  • Steady state (150K) 代表主機端實際獲得的效能。
  • 消耗比例 = (原始能力 - 實際效能) / 原始能力。

Detail

在 Fresh state 下沒有 GC 干擾，400K IOPS 可以視為該 SSD 控制器與 NAND Flash 陣列能處理的「總可用寫入頻寬」。進入 Steady state 後，主機端測得的 IOPS 掉到 150K。這意味著 SSD 將剩餘的運算與頻寬資源都拿去背景執行 GC (包含讀取 Valid pages、寫入新 Block 以及 Erase 舊 Block) 了。

  • 總頻寬能力 = 400K 操作單位
  • 主機佔用 = 150K 操作單位
  • GC 佔用 = 400K - 150K = 250K 操作單位
  • GC 消耗比例 = 250K / 400K = 0.625 = 62.5%
    換句話說，SSD 內部有超過六成的力氣都在做垃圾回收，只有不到四成的力氣在服務你的應用程式。

如果你要設計一個 write-intensive 的 key-value store 系統，在選擇 SSD 時你會優先考慮哪些 steady-state 相關的指標？為什麼 OP 比例可能比標示容量更值得關注？

Answer

優先考慮 Steady-state Random Write IOPS、P99/P99.9 Tail Latency 以及 DWPD (耐久度)。OP 比例比標示容量重要，因為高 OP 能從硬體底層直接壓制 WAF，確保寫入密集的場景下不會發生延遲失控與提早損壞。

Key Concept

  • 關鍵指標: Steady-state IOPS、QoS (Tail Latency)、Endurance (TBW/DWPD)。
  • OP 的價值: 用容量換取效能一致性與壽命。

Detail

針對 Write-intensive 的 Key-Value Store (如 RocksDB, Cassandra)，資料會頻繁被覆寫或 Compaction，這會對 SSD 造成龐大的寫入壓力。
選購時不能只看「最高標示速度」，因為那都是 Fresh state 的假象。必須檢視廠商提供的Steady-state 4K Random Write IOPS以及Quality of Service (QoS)（例如保證 99.99% 的 I/O 在 2ms 內完成）。
為何 OP 比例比總容量更重要？如果你買了 1TB 的消費級 SSD (低 OP) 塞進伺服器，密集的寫入會讓 GC 瘋狂運作，WAF 飆高到 3 或 4 以上。這不僅會讓延遲出現數十毫秒的 Spike 卡死資料庫，高 WAF 更會成倍數消耗 NAND 的 P/E Cycle，讓 SSD 幾個月就報銷。相反地，買 800GB 的企業級 SSD (28% OP)，雖然少了 200GB 的容量，但其高 OP 能將 WAF 壓制在接近 1，提供堅若磐石的延遲與數倍以上的壽命，這才是架構師該在意的。

    1. WAF 最初接近 1.0，直到 free blocks 耗盡並觸發 GC 後，WAF 才開始上升並最終穩定在一個大於 1 的數值。

    Answer

    WAF 最初接近 1.0，直到 free blocks 耗盡並觸發 GC 後，WAF 才開始上升並最終穩定在一個大於 1 的數值。

    Drive B 較高的 OP 比例降低了 WAF，這代表控制器在 GC 期間搬移有效頁面所消耗的內部頻寬較少，進而保留了更多頻寬給主機 I/O。

    1. SSD 內部的 DRAM 快取已完全飽和，迫使 FTL 必須將 Mapping Table 儲存在較慢的 NAND Flash 中，而非高速記憶體中。
    1. 控制器已耗盡了所有乾淨（erased）的區塊，現在必須在處理主機端寫入請求的同時，同步執行 garbage collection 以產生新的可寫入空間。
    1. NAND Flash 儲存單元達到了特定的溫度閾值，觸發了韌體對控制器的永久降頻保護機制，以防止硬碟超過其熱設計功耗。

    Answer

    控制器已耗盡了所有乾淨（erased）的區塊，現在必須在處理主機端寫入請求的同時，同步執行 garbage collection 以產生新的可寫入空間。

    解析:

    在全新出廠狀態下，控制器可以直接寫入已抹除的空區塊。一旦所有區塊都被寫入過一次，之後的每一次新寫入都必須伴隨著「清理舊區塊」的動作。120,000 IOPS 代表了該控制器在「搬移有效資料 + 抹除區塊」與「接收新資料」之間達到的平衡。

    (1) 快取用盡會影響效能，通常會導致 Jitter，而非長期穩定的 steady state。

    (3) thermal throttling 確實會降低效能，但它通常是動態反應。如果環境降溫，效能會回升。

  1. 在 steady state 下，一顆 SSD 的 latency 分佈如下：
    • p50=0.1 ms
    • p95=0.15 ms
    • p99=25 ms
    • p99.9=60 ms

    根據以上數據，最合理的解釋是什麼？

    1. Wear leveling 將資料搬移到較低 P/E cycle 的 block
    1. NAND program time 隨著 P/E cycle 增加
    1. Garbage Collection 在 free block 接近耗盡時觸發大量 data migration
    1. SSD controller clock frequency 在高負載時降低
    Answer

    Garbage Collection 在 free block 接近耗盡時觸發大量 data migration

    解析:

    這組數字表示：大多數 request 的延遲非常低，但在高百分位時延遲突然大幅上升， 顯示系統存在明顯的 tail latency spike。

    • p50=0.1 ms：代表大多數 request 非常快
    • p95=0.15 ms：代表連大部分偏慢的 request 也仍然很快
    • 但 p99=25 ms、p99.9=60 ms：代表只有極少數 request 突然變得非常慢

    這正是 steady state 下 GC（garbage collection）造成的典型現象。 原因是在 steady state 中，SSD 裡大部分 block 都已經被寫過

    • 新寫入不再能永遠直接使用全新的 erased block
    • controller 必須回收空間 這些 GC 工作會與 user I/O 競爭 NAND die/plane 的時間，導致少數 request 被卡住很久

    (1) Wear leveling 確實會搬移資料，因此看起來也可能造成額外延遲。但它通常是 較為平滑且 background 的操作，目的是讓所有 block 的 P/E cycle 分布更平均，而不是在空間即將耗盡時緊急回收空間。 因此 wear leveling 的影響通常是：

    • 輕微增加整體 write latency
    • 或稍微降低平均 throughput 它通常不會造成題目所描述的極端 tail latency 分佈

    (2) P/E cycle 增加對 latency 造成的影響通常比較漸進，它比較像是整體分佈慢慢右移：p50、p95 可能都會一起增加。不會造成這種「前 95% 幾乎不受影響，但 p99 突然大到數百倍」的形狀

    (4) 這個選項看起來合理，因為 controller 降頻確實可能讓整體延遲變高；但它不符合題目的延遲分佈形狀。 若是 controller clock frequency 降低，影響通常會比較全面且連續： 不只是少數 request 變慢，而是大部分 request 都會一起變慢

  1. 在相同製程技術與目標容量（如 1TB）的基準下，比較 QLC 與 SLC SSD 的硬體設計與可靠性機制，下列敘述何者最為精確？
    1. QLC SSD 因為更頻繁地打電壓進 Cell 中，其資料保存時間 (Retention Time) 優於 SLC
    1. 相較於 QLC，SLC SSD 必須配置更高比例的 OP (Over-Provisioning) 空間來應對垃圾回收 (GC)
    1. 為了應對較高的原始錯誤率 (RBER)，QLC 的每個物理 Page 通常配備比 SLC 更大的 Spare Area (OOB)
    1. QLC SSD 中的 SLC Cache 通常是由物理上獨立、造價昂貴的專用 SLC 顆粒組成
    Answer

    為了應對較高的原始錯誤率 (RBER)，QLC 的每個物理 Page 通常配備比 SLC 更大的 Spare Area (OOB)

    解析:

    QLC 的電壓層級極為密集（16 層），對雜訊極其敏感導致 RBER 較高。為了維持資料可靠性，控制器必須使用更強大的糾錯碼（如 LDPC），因此每個 Page 需要預留更多的 Spare Area (OOB 空間) 來儲存更長的 ECC 校驗資訊。

    (1) QLC 的電壓判定區間（Voltage Margin）極窄，微小的電荷洩漏就會導致判讀錯誤，因此其資料保存能力（Retention Time）明顯弱於電壓區間寬廣的 SLC。

    (2) 事實上，QLC 因為 P/E cycle 極低且 WAF 對壽命影響劇烈，在設計上更依賴較大的 OP 空間來降低 WAF 並提升穩態效能；而 SLC 雖然也需要 OP，但其原生耐用度較高，對 OP 比例的依賴程度相對 QLC 較低。

    (4) 現代 QLC SSD 多採用「模擬 SLC pSLC 模式」，即透過韌體讓 QLC Cell 僅存儲 1-bit 電壓狀態來充當 Cache，以兼顧效能與成本，而非使用物理獨立的 SLC 顆粒。

  1. 一個長期存放冷資料 (Cold Storage) 的資料中心計畫將現有的硬碟汰換為成本較低的 QLC SSD。 考慮到 QLC 的物理特性以及該資料中心「讀多寫極少」的工作負載模式，哪一種機制適合用來防止資料遺失？
    1. 提高損耗均衡 (Wear Leveling) 演算法的執行頻率
    1. 降低裝置的每日寫入量 (DWPD) 額定值
    1. 增加 Over-provisioning (OP) 空間比例
    1. 實施定期資料掃描與重刷 (Periodic Data Scrubbing/Refresh)
    Answer

    實施定期資料掃描與重刷 (Periodic Data Scrubbing/Refresh)

    解析:

    在「讀多寫少」的冷儲存情境下，雖然對 Endurance 的磨損極低，但資料長時間存放會面臨 Retention 問題。 由於 QLC 的電壓邊限 (Voltage Margins) 非常窄，電荷洩漏 (Charge Leakage) 極易導致位元翻轉。 定期讀取並重新寫入資料 (Refresh) 能校正漂移的電壓，會是適合的方法。

    (1) Wear Leveling 的目的是確保所有 Flash Block 磨損程度一致，主要解決的是 Endurance 問題。 但在「讀多寫極少」的工作負載下，根本沒有足夠的寫入動作去觸發「損耗」，因此提高其頻率對保護「已經寫入且長期靜止」的冷資料沒有意義。

    (2) DWPD 是衡量 Endurance 的指標。雖然 QLC 的 Endurance 較低，但在「讀多寫極少」的環境中，本來就不會達到寫入上限。 降低 DWPD 對於防止已存放在 NAND 晶片中資料因時間和溫度產生的 Retention 失效沒有物理上的幫助。

    (3) 增加 OP 空間主要目的是為了降低 write amplification (WAF) 並提升 Endurance。 但題目設定的工作負載是「寫入極少」，代表 P/E cycles 的消耗並非主要瓶頸，增加 OP 無法解決電荷隨著時間自然洩漏導致的 Retention 問題。

    系統 Y → 型號 A 寫入頻率極低，idle time 充裕，controller 早已在背景完成 GC，WAF 接近 1。 此情境下 OP 邊際效益趨近於零；選型號 A 可多得 160 GB 可用容量，成本效益更佳。

    (1) 廠商標示的 IOPS 為 Fresh State 測試數據，無法反映 Steady State 下的 tail latency 表現。 此外，系統 Y 寫入頻率極低，高 OP 對耐久性的幫助微乎其微，反而白白損失 160 GB 可用容量。 分配方向與選擇理由皆有誤。

    (3) 分配方向正確，但理由有誤。 在一般 Greedy-policy-based GC 演算法下，controller 優先選擇 Valid Ratio 最低的 Block， 目的是最小化搬移成本，而非搬移更多 Valid Pages。 OP 較高讓 GC 能挑到更「划算」的 Block，WAF 因此更小，而非因「掌控更精細」而改善。

    (4) OP 的效益取決於寫入強度與 Duty Cycle，並非放諸四海皆準。 系統 Y 寫入極為稀少且以循序為主，GC 壓力本就接近於零， 型號 B 多出的 OP 形同閒置，卻讓系統 Y 損失 160 GB 可用容量。

  1. 某新創公司正在評估兩款 1TB 容量的 NVMe SSD 作為核心資料庫的儲存媒體。其中，A 款為消費級 SSD（保留極少的 Over-Provisioning 空間）；B 款為企業級 SSD（保留了高達 28% 的 Over-Provisioning 空間）。
    一位資淺工程師對這兩款全新且完全空白（Fresh Out of Box, FOB）的 SSD 執行了 10 分鐘的隨機寫入效能測試（random write benchmark）。測試結果顯示，A 款與 B 款的 IOPS 幾乎一樣高，工程師因此結論：「多花錢買大 OP 空間的企業級 SSD 對隨機寫入效能毫無幫助」。
    根據 SSD 的「Steady-State」與「garbage collection」原理，這位工程師的測試方法論犯了什麼致命的錯誤，導致其結論完全失效？
    1. 工程師使用了Random write來進行測試。在 SSD 的硬體架構中，Over-Provisioning（OP）空間主要是用來加速 sequential write 的頻寬。如果改用大區塊的連續寫入進行測試，即使在全新的 FOB 狀態下，B 款企業級 SSD 也能立刻展現出效能優勢。
    1. 因為 SSD 處於全新的 FOB 狀態，所有的 physical blocks 都是空白的。在最初的 10 分鐘內，FTL 只需要不斷尋找新的空白區塊寫入，完全不需要啟動背景的 GC，此時的 WAF 完美等於 1。要看出 OP 空間對效能的真實價值，必須先對 SSD 進行預處理（Preconditioning，例如寫滿整顆磁碟數次），迫使其進入缺乏空白區塊、GC 頻繁運作的Steady-State後再進行測試。
    1. 在全新的 FOB 狀態下，SSD 控制器會強制開啟SLC SLC Caching。這個模式會將所有的 TLC 或 QLC 顆粒模擬成 SLC 來寫入，從而掩蓋了 OP 空間的大小差異。必須透過軟體指令手動關閉 SLC 快取，才能測出穩定態的真實效能。
    1. 因為 10 分鐘的測試時間太短，NVMe 控制器內部的 DRAM Cache 還沒有被完全寫滿。在快取耗盡之前，所有的隨機寫入都會被暫存在 DRAM 中並回報完成，導致 A 款與 B 款的效能看起來一樣。只要將測試時間延長到 30 分鐘讓 DRAM 滿載，就能看出兩者的差異。
    Answer

    因為 SSD 處於全新的 FOB 狀態，所有的 physical blocks 都是空白的。在最初的 10 分鐘內，FTL 只需要不斷尋找新的空白區塊寫入，完全不需要啟動背景的 GC，此時的 WAF 完美等於 1。要看出 OP 空間對效能的真實價值，必須先對 SSD 進行預處理（Preconditioning，例如寫滿整顆磁碟數次），迫使其進入缺乏空白區塊、GC 頻繁運作的Steady-State後再進行測試。

    解析:

    這是正確的。在 SSD 的生命週期中，全新的 FOB（Fresh Out of Box）狀態會展現出極高且不真實的效能，因為此時完全沒有 GC 的開銷。當磁碟被寫滿並開始覆寫時，效能會經歷「懸崖式下跌」並進入 Steady-State。在穩定態下，大容量的 Over-Provisioning（OP）空間能讓 GC 更容易找到 invalid pages 進行回收，大幅降低 WAF 並維持較高的 IOPS 底線。工程師只測了最初的 10 分鐘，根本還沒把磁碟寫滿觸發 GC，因此無法測出 OP 的真實效益。

    (1) 這是對 OP 空間用途的嚴重誤解。Sequential write 會讓整個 Block 依序填滿，失效時也會整塊失效，GC 回收時幾乎不需要搬運有效資料，因此本來就不太依賴 OP 空間。OP 空間最大的價值，正是用來拯救會產生嚴重碎塊與高 WAF 的Random write負載。

    (3) 這個選項將不同的快取機制混為一談。SLC Caching 確實是現代消費級 SSD 用來短暫提升效能的機制，但它與 SSD 是否進入「Steady-State」的核心定義（即全碟寫滿、GC 與寫入達到進出平衡）不同。要測量真實的企業級效能，標準的做法是透過全碟覆寫（Preconditioning）來耗盡 SLC 空間與空白區塊，逼出底層的真實速度，而不是單純尋找手動關閉快取的軟體指令。

    (4) 這是一個常見的迷思。雖然 DRAM 快取確實能吸收突發的寫入，但 10 分鐘的連續隨機寫入早就遠遠超過了任何商用 SSD 內部幾 GB 的 DRAM 容量。導致效能看起來一樣的真正原因，是底層 NAND flash 還有大量的 free blocks 可以使用，尚未觸發 GC 導致效能衰退，而不是因為資料還停留在 DRAM 裡。

  1. 你五年前購買了一顆全新的 1 TB TLC SSD，使用至今其平均 P/E cycle count 約為 2500 次。你打算將這顆老化但仍可運作的 SSD 用於個人資料的異地離線備份，且預計未來五年內完全不通電。請問這樣做最主要的風險是什麼？
    1. 即使五年斷電後部分資料發生 bit error，SSD 內部的 ECC 機制在重新通電時能完整修正這些錯誤，因此資料不會遺失。
    1. SSD 與 HDD 一樣適合長期離線儲存。只要不是 controller 故障或人為物理損害，不會因為長期放置而導致資料損壞。
    1. 長時間斷電後，NAND cell 中的電荷會逐漸洩漏，導致儲存的資料毀損。但這屬於資料層面的損壞，cell 的物理結構並未因此失效，重新抹除並寫入後仍可繼續使用。
    1. 由於尚未達到該顆 TLC SSD 的額定 P/E cycle 壽命，且目前仍可正常運作，因此可以安全地長期離線存放資料而不會有資料損壞的風險。
    Answer

    長時間斷電後，NAND cell 中的電荷會逐漸洩漏，導致儲存的資料毀損。但這屬於資料層面的損壞，cell 的物理結構並未因此失效，重新抹除並寫入後仍可繼續使用。

    解析:

    正確。NAND flash 的 data retention 取決於 cell 中電荷的保持能力。隨著 P/E cycle 累積，tunnel oxide 磨損加劇，電荷洩漏速率增加。已使用 2500 次 P/E cycle 的 TLC 接近額定壽命，其 data retention 時間可能從全新時的數年縮短至數週到數月，五年斷電極有可能超出安全範圍。然而 retention failure 的本質是電荷流失，而非 cell 結構的物理失效，因此 cell 仍可被重新抹除與寫入。

    (1) ECC 確實能修正一定數量的 bit error，但其修正能力有上限。在高 P/E cycle count 加上長時間斷電的雙重條件下，累積的 bit error 數量很可能超出 ECC 的修正能力，產生 uncorrectable error，導致資料永久遺失。

    (2) HDD 使用磁性儲存，資料保存期限可達數十年，遠長於 NAND flash 的電荷式儲存。NAND flash 的 cell 依賴電荷維持資料，長時間斷電後電荷會自然洩漏，這是物理特性而非故障。對於長期離線儲存或冷儲存場景，retention 才是主要挑戰，不能將 SSD 與 HDD 等同看待。

    (4) 這個選項混淆了 endurance 與 retention。P/E cycle 壽命衡量的是 NAND 能承受多少次寫入（endurance），而非資料在斷電後能保存多久（retention）。高 P/E cycle count 的 NAND 因 tunnel oxide 受損加劇，電荷洩漏速率加快，使得斷電後的 data retention 時間大幅縮短。「還沒寫壞」不代表「能安全放著不通電」。

  1. 多數人在開箱測試全新 SSD 時，測量到的皆為 fresh state 的高效能，但在真實伺服器環境中，長期運作的 SSD 會進入效能顯著衰退的 steady state，並帶來嚴重的 tail latency spike（如 p99 延遲飆高到數十毫秒）。假設你有一個對延遲極度敏感的 OLTP 系統，並對比了一顆 7% OP 的消費級 SSD 與一顆 28% OP 的企業級 SSD。下列關於 steady state 下延遲變化機制的敘述，何者最符合硬體與系統運作的邏輯？
    1. 在 steady state 下，NAND flash 必須同時服務使用者的 I/O 請求與 background GC 所需的 block erase 與資料搬移。當 OP 達到 28% 時，SSD 隨時有更多空閒的 block，使得 GC 可以挑選 invalid page 比例更高的 block 來回收。這不僅降低了 WAF，也減少了 GC 與 foreground I/O 競爭底層頻寬的強度，進而大幅減輕 tail latency spike。
    1. steady state 中出現的 tail latency spike，主要是因為 OS page cache 預設採用 write-back caching 機制，導致 dirty page 會以不可預測的巨大 batch 一次性 flush 到硬碟。只要透過 fsync() 強制程式改為 synchronous I/O 模式，即可讓寫入直接下到硬碟，進而消除底層硬體 GC 造成的 tail latency。
    1. 為了緩解 steady state 下的 tail latency，企業級 SSD 廣泛依賴 background GC 在系統閒置時主動回收空間。因此在 OLTP 這類持續高負載的環境中，只要有 28% 的 OP 搭配 background GC，就能完全避免寫入時觸發 GC，使 p99 延遲永遠保持與 fresh state 一致。
    1. 企業級 SSD 的 28% OP 專門用來將 FTL 的全域 mapping table pin 在內部。在 steady state 時，由於 mapping table 完全不需要在寫入時同步更新至外部 NAND flash，徹底消除了因為 Read-Modify-Write 造成的 latency spike。
    Answer

    在 steady state 下，NAND flash 必須同時服務使用者的 I/O 請求與 background GC 所需的 block erase 與資料搬移。當 OP 達到 28% 時，SSD 隨時有更多空閒的 block，使得 GC 可以挑選 invalid page 比例更高的 block 來回收。這不僅降低了 WAF，也減少了 GC 與 foreground I/O 競爭底層頻寬的強度，進而大幅減輕 tail latency spike。

    解析:

    Tail latency 的主因來自於 background GC 正在執行耗時較長的 block erase 或搬移大量 valid page，導致 foreground I/O 請求被迫排隊等待。OP 比例越高的企業級 SSD，其 GC 不需要等到空間極度緊迫才啟動，且更容易找到含有大量 invalid page 的 block 進行低成本的回收。這有效降低了 I/O 競爭，是控制 steady state 下 tail latency 的關鍵硬體優勢。

    (2) 頻繁呼叫 fsync() 會失去來自 OS page cache 延遲波動的 smoothing 功能，迫使程式進入 blocking state 等待硬體完成操作。在 steady state 下，這反而會讓程式直接受限於 NAND 底層動輒數毫秒的物理抹除延遲，進而惡化觀測到的 tail latency。

    (3) 在持續高負載環境下，SSD 缺乏足夠的 idle time 來執行 background GC，最終會觸發 foreground GC，導致寫入效能受限於回收速度，即使擁有 28% 的 OP，也只能減輕延遲的峰値與頻率，無法完全抵銷 steady state 下邊寫邊收的物理限制，因此無法達到與 fresh state 相同的效能。

    (4) OP 空間是開放給 GC 靈活運用的隱藏 NAND flash 容量，用來吸收寫入與優化垃圾回收效率。FTL 的 mapping table 主要是存放在 SSD 的內建 DRAM 或藉由 HMB (Host Memory Buffer) 存放於系統記憶體中，並非將龐大的 OP 空間浪費在 pin mapping table 上。

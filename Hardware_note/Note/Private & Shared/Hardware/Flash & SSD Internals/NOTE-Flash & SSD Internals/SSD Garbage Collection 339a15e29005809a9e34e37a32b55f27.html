SSD Garbage Collection

你可能有過這種經驗：一邊工作一邊用 Steam 裝遊戲，寫入大量資料的時候，系統突然頓了一下，滑鼠移動不太順，或是正在存檔的程式卡了半秒鐘。那個短暫的卡頓，很可能就是你 SSD 內部的 garbage collection（GC）正在跟你的工作搶頻寬。

FTL 的 out-of-place write 策略解決了「不能覆寫」的問題，但製造了一個新問題：隨著寫入持續進行，NAND flash 上會累積越來越多的 invalid page（舊版本的資料），而這些 page 所在的 block 無法直接重新使用，因為一個 block 裡通常同時包含 valid page 和 invalid page。如果不處理，SSD 最終會耗盡所有空白 page 而無法寫入。GC 就是 SSD 韌體中負責回收這些空間的機制，它的設計直接決定了 SSD 的寫入效能、延遲一致性、以及使用壽命。

Key Word Definition/ Discussion
Garbage collection

GC 的存在是因為 NAND Flash 的物理特性："Write by Page, Erase by Block"。

SSD 控制器用來：

回收包含無效資料（invalid pages）的 block，重新變成可寫入空間的機制

GC 的基本流程

GC 的運作可以分成三個步驟：

  1. 選擇 victim block：從所有包含 invalid page 的 block 中，依據某種策略選出一個 block 來回收。
  1. 搬移 valid page：把 victim block 中仍然有效的 page 讀出來，寫到其他有空白 page 的 block 中，同時更新 FTL mapping table。
  1. 抹除 victim block：整個 block erase，變成可以重新寫入的 free block。

這裡的核心開銷在步驟 2：搬移 valid page。每搬移一個 page 就需要一次 read 和一次 write，而這些 read/write 與使用者的 I/O 共享 NAND flash 的頻寬。如果一個 block 裡有 200 個 valid page（總共 256 個），那回收這個 block 需要 200 次額外的 read + write，但只換來 256 個空白 page。效率不高。反之，如果一個 block 裡只有 10 個 valid page，那只需 10 次搬移就能換來 256 個空白 page，效率很好。

這就引出了 victim block selection 的策略問題。

Write Amplification Factor (WAF)

頻繁搬移資料會導致 SSD 實際寫入的資料量大於 Host 端要求的資料量，這就是所謂的「寫入放大」現象。

關鍵結論： 當 SSD 空間越滿，回收效率越差，寫入放大越嚴重。

假設 Block 的有效資料比例為u (utilization)，則回收該 Block 的理論寫入放大倍率為：WAF ≈1−u1​

數據關係對照：

Invalid page vs Valid page

Valid page：目前 mapping table 指向的最新資料

Invalid page：舊資料（已被更新覆蓋，但還在 flash 裡）

每個 page 有 metadata：

  • valid bit
  • LBA mapping info

Controller 透過這些來判斷 page 狀態

作業系統在刪除檔案時，只會移除檔案系統的目錄指標，不會主動通知 SSD。這會導致 SSD 誤認這些垃圾資料為Valid Page，在 GC 時盲目搬移，造成嚴重的效能浪費。

解法：OS 必須支援並發送TRIM 指令，明確告知 SSD 哪些 LBA (Logical Block Address) 的資料已刪除，讓 SSD 標記為Invalid Page。

Greedy policy vs Cost-benefit policy

Greedy policy: 選 invalid page 最多的 block

Cost-benefit policy: 同時考慮utilization（使用率）& age（資料年齡）

Greedy policy 是最直覺的策略：

挑選 invalid page 數量最多的 block 作為 victim。邏輯很簡單，invalid page 越多代表需要搬移的 valid page 越少，回收的成本最低、效率最高。

Greedy 在大多數情況下表現不差，但它有一個盲點：它不考慮資料的「年齡」。假設有兩個 block：

  • Block A：50% invalid page，但 valid page 裡的資料是「冷資料」（很久沒被更新）
  • Block B：60% invalid page，但 valid page 裡的資料是「熱資料」（頻繁被更新）

Greedy 會選 Block B（invalid 比例高）。但 Block B 的 valid page 很快就會被更新而變成 invalid，如果我們等一下，Block B 可能自然地累積更多 invalid page，到時候回收成本更低。相比之下，Block A 的冷資料可能永遠不會被更新，如果不主動回收，這些 valid page 會一直霸佔空間。

Cost-benefit policy 就是考慮這個因素的策略。

它的選擇公式大致是：

benefit = (1 - utilization) * age / (2 * utilization)

其中 utilization 是 block 中 valid page 的比例，age 是 block 中資料的平均年齡（距離上次被寫入的時間）。這個公式傾向選擇那些「utilization 低且資料老舊」的 block，因為老舊資料不太可能自己變成 invalid，不主動清理就會一直浪費空間。

實務上，許多 SSD 使用 greedy 的變種或更複雜的 heuristic，因為 cost-benefit 需要追蹤每個 block 的年齡資訊，增加了實作複雜度。

Over-provisioning

給 GC 留的緩衝空間

SSD 的實際 NAND flash 容量比使用者看到的容量大。例如一顆標示為 1 TB 的 SSD，內部可能有 1.12 TB 的 NAND flash。多出來的 12% 就是 over-provisioning（OP），使用者無法存取這些空間。

OP 的主要用途就是讓 GC 有足夠的「週轉空間」。想像一個類比：你有一個書架，所有格子都塞滿了書。如果你想整理某一格（把不要的書丟掉），你需要一個暫時放書的地方。如果書架完全滿了，連一個暫放的空間都沒有，整理就無法進行。OP 就是那個暫放空間。

類型OP
Consumer SSD~7%
Enterprise SSD~28%

GC 輕鬆GC 緊急
WA 低WA 高

OP 比例直接影響 GC 的效率：

  • OP 越高：free block 越多，GC 不需要在空間極度緊張時才運作，可以從容地選擇最佳 victim block。搬移的 valid page 比例較低，write amplification 較小。
  • OP 越低：free block 稀缺，GC 經常在「快沒空間了」的緊急狀態下運作，被迫選擇 valid page 比例較高的 block 來回收，write amplification 增加。

企業級 SSD 的 OP 通常為 28%（標示 800 GB 但內部有 1024 GB NAND），而消費級 SSD 通常只有 7%（標示 1 TB 但內部有 1074 GB NAND）。這也是企業級 SSD 在持續寫入下效能更穩定的原因之一。這就是為什麼企業級 SSD 比消費級貴好幾倍：你買的不只是更高的耐久度，更是那多出來 20% 的「隱藏容量」帶來的 GC 效率優勢。資料中心為了穩定的 tail latency，願意花三倍的錢買只多了一點 OP 的 SSD。

OP 還有另一個用途：當某些 block 的 P/E cycle 耗盡或出現壞 cell 時，OP 區域的 block 可以作為替換，延長 SSD 的可用壽命。

Wear leveling

平衡 P/E cycle 使用

每個 block 的 P/E cycle 有上限（例如 TLC 約 3,000 次）。如果某些 block 被頻繁地 erase 而其他 block 幾乎不動，那些高使用率的 block 會先壞掉。即使其他 block 還很健康，SSD 的有效容量也會因為壞 block 的累積而縮小，最終影響可靠性。

Wear leveling 的目標是讓所有 block 的 P/E cycle 使用量盡量平均。這分為兩種策略：

Dynamic wear leveling：在 GC 選擇 victim block 時，優先選擇 P/E cycle 較低的 block 作為搬移目的地。這種方式只影響被 GC 處理過的 block，對於一直存放冷資料而從未被 GC 動過的 block 沒有效果。

Static wear leveling：主動把存放在低 P/E cycle block 上的冷資料搬到高 P/E cycle 的 block 上，然後把低 P/E cycle 的 block 釋放出來給 GC 使用。這樣冷資料不會一直霸佔「年輕」的 block，讓所有 block 的磨損更加均勻。

Static wear leveling 的開銷比 dynamic 大（需要額外搬移本來不需要動的資料），但對延長 SSD 整體壽命更有效。實際的 SSD 韌體通常會結合兩種策略，在效能和壽命之間取得平衡。

值得注意的是，wear leveling 和 GC 的 victim selection 策略有時會衝突。Greedy GC 想回收 invalid page 最多的 block（效率最高），但 wear leveling 可能要求對低 P/E cycle 的 block 做更多操作。SSD 韌體需要在這些目標之間做適當的權衡。

  • GC 的目標：挑選 Invalid 最多的 Block 來回收，追求「最低的搬移開銷與最高效率」。
  • WL 的目標：挑選 P/E Cycle 最低的 Block 來操作，追求「壽命平均」，這通常意味著要強制搬移有效資料。
    兩者在底層邏輯上是互相拉扯的。過度追求 WL 會導致 WAF 暴增（搬移太多非必要資料）；完全偏向 GC 則會使 SSD 提早陣亡。優質的 SSD 韌體必須在這兩個指標間設定動態閾值，取得最佳權衡。

Victim selection

GC 選擇哪個 block 來回收的策略

選擇時會考慮：

  • invalid page 數量
  • valid page 數量
  • block age
  • erase count（P/E cycles）
  • 是否為 hot / cold data

常見策略：

  • Greedy
  • Cost-benefit
  • Wear-aware policy（結合 wear leveling）

Key Concept

Out-of-place write與 Erase-before-write

Detail

當資料要更新時，SSD 不能直接在原位覆蓋，必須將新資料寫在一個新的空白 Page，並將舊 Page 標記為 Invalid（無效）。隨著時間推移，Block 會充滿無效 Page，但因為抹除操作必須以整個 Block 為單位，不能單獨抹除一個 Page，所以需要 GC 將多個 Block 中的有效資料搬移、集中，最後將整塊舊 Block 抹除以回收空間。

理解 GC 的基本流程：選擇 victim block、將 valid page 搬移到其他 block、抹除整個 block 以回收空間

Answer

挑選受害者（Victim）→ 搬移有效資料（Valid Page Copy）→ 抹除（Erase）

Key Concept

釋放連續的空白空間

Detail

  1. 選擇 Victim Block: 根據演算法（如 Greedy）挑選無效資料最多的 Block。
  1. Valid Page Move: 將該 Block 內剩餘的有效資料讀出並寫入另一個乾淨的 Block。
  1. Block Erase: 確定資料遷走後，將整個 Victim Block 抹除，其狀態變回可用空間（Free Block）。

了解 over-provisioning 的用途，知道預留額外空間如何讓 GC 有足夠的緩衝空間運作

Answer

提供額外的緩衝空間，減少 GC 頻率並降低寫入放大（WAF）。

Key Concept

Write Amplification

Detail

OP 是使用者看不見的預留空間。如果 SSD 塞得太滿，GC 每次能回收的空間極少，卻要搬移大量有效資料，導致效能低落。有了 OP，控制器有更多的「餘裕」來調度，就像大風吹遊戲中多放幾張椅子，讓換位子的過程更順暢。

理解 greedy policy 與 cost-benefit policy 在 victim block selection 上的差異與適用情境

Answer

Greedy 只看現在誰最空；Cost-benefit 考慮了資料的冷熱（年齡）。

Key Concept

Data Locality（資料局部性）與冷熱分離

Detail

  • Greedy: 永遠選有效 Page 最少的。缺點是若該 Block 是冷資料，搬移後它可能很久都不會再變動，造成不必要的寫入。
  • Cost-benefit: 公式考慮了 (1-u)*age。如果一個 Block 雖然有效資料多一點點，但它已經放很久了（冷資料），選它回收能讓系統趨於穩定；反之，太年輕（熱資料）的 Block 即使很空也不急著收，因為它可能很快又會產生更多無效 Page。

知道 wear leveling 的目的是讓所有 block 的 P/E cycle 使用量盡量平均，避免部分 block 提早損壞

Answer

平均分配每個 Block 的 P/E cycle，防止特定 Block 過早損壞。

Key Concept

延長 SSD 壽命（Endurance）

Detail

NAND Block 有抹寫次數限制。Dynamic Wear Leveling 在寫入時選擦拭次數少的 Block；Static Wear Leveling 則會主動搬移長期不動的冷資料，把該 Block 騰出來給熱資料使用，確保「長壽」的 Block 也能分擔工作負荷。

Key Concept

Valid Page Copy overhead

Detail

為了回收這一個 Block，必須把那 200 個有效 Page 搬走，這產生了額外的 200 次讀與寫。最終整個 Block 抹除後，我們獲得了 256 個空白 Page，但其中 200 個空間被剛才搬走的資料占用了，淨增加的可用空間僅為 256 - 200 = 56。這也體現了為何有效資料占比高時 GC 效率極低。

為什麼 greedy policy 在冷熱資料混合的 workload 下可能不是最佳策略？請用具體的 block 狀態舉例說明 cost-benefit policy 會做出什麼不同的決策。

Answer

Greedy 可能會頻繁搬移「即將變為無效」的熱資料，浪費寫入次數。

Key Concept

Write Efficiency

Detail

假設 Block A 有 10 個 valid pages 但資料很熱（馬上會更新），Block B 有 20 個 valid pages 但資料極冷。Greedy 會選 A，搬移 10 頁。但如果等一下，A 的 10 頁可能自己變無效了，根本不用搬。Cost-benefit 會考量年齡，選擇回收 Block B，讓熱資料有更多時間在 A 裡面「自行失效」。

一顆企業級 SSD 有 28% OP，一顆消費級 SSD 有 7% OP。在持續 random write workload 下，哪顆 SSD 的 write amplification 會比較低？為什麼？

Answer

28% OP 的 SSD 寫入放大（WAF）會明顯較低。

Key Concept

Probability of finding empty blocks

Detail

較大的 OP 意味著 SSD 內部有更多閒置空間。在隨機寫入下，較高的 OP 能確保每個 Block 被挑選為 Victim 時，其有效資料占比（Utilization）平均較低，搬移成本隨之下降，根據公式 WAF 約等於 1/(1−Utilization)

如果一顆 SSD 只使用 dynamic wear leveling 而沒有 static wear leveling，在什麼情境下會出現部分 block 提早耗盡 P/E cycle 的問題？

Answer

存放在冷資料（如作業系統檔案）的 Block 會一直保持低 P/E cycle，而其他 Block 會提早損耗。

Key Concept

Static vs. Dynamic leveling

Detail

Dynamic 只針對「當前要寫入的資料」選 Block。如果有些資料寫入後幾年不動，占用的 Block 就永遠不會被抹除。這會導致可用的循環 Block 變少，剩下的 Block 必須更頻繁地被抹寫，縮短整體壽命。

GC 的 victim selection 和 wear leveling 的目標可能會衝突。請描述一個具體的情境，說明 SSD 韌體在這兩個目標之間需要做什麼取捨。

Answer

GC 想選「最空」的 Block（為了效率）；Wear Leveling 想選「P/E cycle 最少」的 Block（為了壽命）。

Key Concept

Efficiency vs. Endurance Trade-off

Detail

某個 Block 可能包含大量無效資料（GC 的完美目標），但它的 P/E cycle 已經很高了。如果為了效率回收它，會讓它更接近損壞。韌體必須在兩者間取捨，有時為了長遠壽命，會忍痛回收一個有效資料較多、但 P/E cycle 較低的 Block。

    將數值代入公式：Block X 為 ((1 - 0.25) * 60) / (2 * 0.25) = 90；Block Y 為 ((1 - 0.10) * 2) / (2 * 0.10) = 9。 Cost-benefit 策略會優先選擇分數高的 Block X。

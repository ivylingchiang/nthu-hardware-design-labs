Flash Translation Layer

"We can solve any problem by introducing an extra level of indirection."

FTL是介於SSD前端和後端之間的一個轉換層，前端指的是和Host用Protocol溝通的那邊，後端是真正儲存資料的實體的Nand Flash這邊。以前傳統的Hard Disk可以直接從Host指定把資料存在硬碟裡的任何區域，SSD中間多一層FTL就是傳統硬碟和固態硬碟不同之處，和固態硬碟使用的Nand Flash特性有關。

必須先Erase，才能Program。寫入之前要先抹除，沒有抹除而直接複寫的話資料會壞掉讀不出來。而且抹除的時間 » 寫入的時間 » 讀取的時間。

抹除和讀寫的單位不一樣，抹除的最小單位是一個Block，讀寫的最小單位是一個Page，一個Block大約是64個Page(或更多)。

Nand Flash是有壽命的，他的壽命可以用Block的PE Cycle (Program/Erase Cycle)來計算，SLC大概50K次、MLC大概3K次、TLC小於1K次，使用超過這些次數不一定真的會壞掉，但是有很高的機率資料會越來越難讀出來。

資料存進去後，若只一直讀取而不再抹除重寫，周圍的Page裡面儲存的電子(代表0和1的bits)會被讀取的電壓所影響，而造成資料錯誤。

Key Word Definition/ Discussion
Flash Translation Layer(FTL)

主機對 SSD 發出的指令都是以 LBA（Logical Block Address）為單位。但 NAND flash 內部的實體位置會不斷變動：同一筆資料可能因為 garbage collection 被搬到不同的 physical page。如果沒有 FTL，主機每次讀取都需要知道資料目前在哪個 physical page，這顯然不切實際。

它透過建立間接層（Indirection Layer），將主機端的連續邏輯世界與 NAND Flash 破碎、動態的實體世界解耦合。

FTL 的四大核心任務

  • Address Translation：維護 LBA 到 PBA 的映射。
  • Garbage Collection（GC）：清空 Invalid Pages 以釋放可用空間。
  • Wear Leveling（抹寫均衡）：確保所有 NAND Block 的抹除次數平均，延長 SSD 壽命。
  • Bad Block Management（壞區塊管理）：標記並隔離出廠或使用中產生的損壞 Block。

Reference:

LBA(Logical Block Address) vs PBA(Physical Block Address)

LBA (Logical Block Address)：主機視角（Host View）。由 OS 或檔案系統發出，在主機眼中，儲存空間是「連續且固定」的。

PBA (Physical Block Address)：實體視角（Physical View）。NAND Flash 內部的真實位置。因為 FTL 的 Wear Leveling 和 GC 機制，同一筆資料（同一個 LBA）在 SSD 內部的物理位置是「離散且會不斷變動」的。

Reference:

Mapping Table

FTL 維護一張 mapping table，記錄每個 LBA 對應到哪個 PBA（Physical Block Address，更準確地說是 physical page address）。

FTL 依賴 Mapping Table 來進行 LBA 到 PBA 的 Lookup。但這張表存在 SRAM 中，具備 Volatile（揮發性），斷電即消失。一旦映射表遺失，整顆 SSD 在邏輯上等同損壞。

持久化策略 (Persistence Mechanisms)：

  • Checkpoint：定期將整張 Mapping Table 寫入 NAND Flash。
  • Logging：每次更新 Mapping 時記錄一筆 Log，開機時 Replay Log 重建表格。
  • Hybrid (Checkpoint + Log)：定期備份整張表，期間的微小變動用 Log 紀錄，兼顧效能與還原速度。
  • 硬體防護 (PLP)：企業級 SSD 會配備大電容（Power-loss protection capacitor），在異常斷電時提供黃金幾毫秒，讓控制器把 SRAM 中的 Dirty Entry (已修改但尚未寫入 NAND 的條目) Flush 到 NAND 中。

這也是為什麼 SSD 通常有一顆大電容（power-loss protection capacitor）：斷電時提供足夠的電力讓 controller 把 SRAM 中的 dirty mapping entry flush 到 NAND flash，確保不會掉資料。

Out-of-place write

Why Out-of-place?

NAND Flash 存在物理限制：Erase-before-write。且抹除單位（Block）大於寫入單位（Page）。若要在原位覆寫，會導致嚴重的延遲，因此必須永遠寫到新的空白位置。

運作流程

  1. 從 free page pool 取得一個空白的 physical page
  1. 把新資料寫入這個 page
  1. 更新 mapping table：將LBA 指向新的 PBA
  1. 將舊的 physical page 標記為 invalid，等待 GC 回收

關鍵影響與副作用：

  • Random 變 Sequential：主機端的 Random Write，經過 FTL 後在 NAND 物理層面都會變成 Sequential Write（一直往空白 Page 寫），這是 SSD 隨機寫入遠勝 HDD 的底層原因。
  • Write Amplification (WA，寫入放大)：因不斷產生 Invalid Page 觸發 GC 搬移有效資料，導致 SSD 實際寫入的資料量大於主機請求的寫入量。

Reference:

Page-level mapping vs Block-level mapping

Page：快、彈性、高記憶體

Block：慢、省記憶體

Mapping table 的粒度是 FTL 設計中最關鍵的取捨。

Page-level mapping：

每個 logical page 獨立映射到一個 physical page。

  • 優點：完全的靈活性。任何 LBA 可以映射到任何 physical page，random write 效能最好。
  • 缺點：mapping table 巨大。以一顆 1 TB SSD 為例，假設 page size 為 4 KB，共有 1 TB / 4 KB = 256M 個 page。每個 entry 需要 4 bytes（32-bit PBA），mapping table 總共需要 256M x 4 bytes = 1 GB 的 SRAM。SRAM 極其昂貴，1 GB 的 SRAM 成本可能比 SSD 本身還高。
Block-level mapping：

以 block 為單位做映射。一個 logical block 內的所有 page 按照 offset 對應到 physical block 內的相同 offset。

  • 優點：mapping table 極小。如果每個 block 有 256 個 page，table 只需要 256M / 256 = 1M 個 entry，約 4 MB 的 SRAM。
  • 缺點：靈活性極差。如果你只更新 block 內的一個 page，必須把整個 block 的有效資料讀出來，寫到新的 block，再更新 mapping。這等於把 random write 變成了整個 block 的 read-modify-write，效能很差。
比較維度Page-level MappingBlock-level Mapping
映射單位Logical Page → Physical PageLogical Block → Physical Block
SRAM 消耗極大（約 SSD 容量的 0.1%）極小
靈活性完全彈性，Random Write 效能極佳靈活性差，更新單一 Page 會牽動整個 Block
小檔寫入效能優秀極差（需執行 Read-Modify-Write）

這裡有一個數字值得記住：page-level mapping 的 SRAM 需求大約是 SSD 容量的 0.1%。
以 1TB SSD、4KB Page Size 為例，Page-level 需要高達 1GB 的 SRAM。SRAM 成本極高，這在消費級產品上是不現實的。

DFTL

既然 page-level 太貴，block-level 太慢，實際的 SSD 怎麼做？答案是 hybrid 方案，其中最具代表性的是 DFTL（Demand-based FTL）。
DFTL 借鑑了作業系統中 Virtual Memory (虛擬記憶體) / Demand Paging 的概念，用有限的 SRAM 拼出接近 Page-level 的效能。

架構與運作原理：

  • NAND Flash：存放完整的 Page-level Mapping Table（Global Translation Directory）。
  • SRAM：只快取最常被存取的 Mapping Entries，稱為 CMT (Cached Mapping Table)。
  • 存取邏輯：
    • CMT Hit：直接在 SRAM 取得 PBA，極速讀寫。
    • CMT Miss：發生類似 Page Fault 的狀況，必須去 NAND 讀取 Translation Page，會產生額外延遲。滿載時需透過 LRU 演算法淘汰舊 Entry。

DFTL 嚴重依賴 Workload 的 Locality。如果遇到極端的 Random Workload，會導致 CMT Hit Rate 暴跌，引發頻繁的 CMT Miss 與 NAND Read，效能會發生斷崖式下降。

DFTL 的效能取決於 CMT hit rate。如果 workload 有良好的 locality（大多數存取集中在少數 LBA），CMT hit rate 高，效能接近 page-level mapping。但如果 workload 是完全 random 的，大量 CMT miss 會產生額外的 NAND flash 讀取（讀 translation page），嚴重影響效能。

除了 DFTL，還有其他混合策略。例如把 NAND flash 空間分成 data block 和 log block：data block 用 block-level mapping，random write 先寫到少量的 log block（用 page-level mapping），等 log block 滿了再 merge 回 data block。這類設計的目標都是一樣的：用有限的 SRAM 預算，在盡可能多的 workload pattern 下提供接近 page-level mapping 的效能。

Reference:

SRAM

SRAM 具備「快、小、貴、揮發性」四大特點，在 SSD 控制器中主要負責兩大任務：

  • Mapping Cache：存放 CMT。
  • Write Buffer：緩衝主機寫入的資料。
  • 系統設計考量：
    • SRAM 太小 → CMT 容量不足，DFTL 效能暴跌。
    • SRAM 太大 → BOM (Bill of Materials) 成本爆炸，失去市場競爭力。

理解 FTL 如何將 LBA（Logical Block Address）映射到 PBA（Physical Block Address），以及為什麼這層轉譯是必要的

Answer

FTL 是一個軟體/韌體間接層，負責將主機看見的連續邏輯位址 (LBA)，翻譯成 NAND Flash 動態變化的實體位址 (PBA)。

Key Concept

Indirection Layer (間接層) / Decoupling (解耦合)

Detail

主機（OS）預期儲存裝置是固定且連續的區塊；但 NAND Flash 因為物理限制，資料位置會因為垃圾回收 (GC) 或抹寫均衡 (Wear Leveling) 不斷搬移。如果沒有 FTL，主機就必須自己管理這些破碎的物理位置。FTL 完美解耦了這兩端，讓主機能像用普通硬碟一樣使用 SSD。

理解 out-of-place write 策略的運作方式：每次寫入都寫到新的空白 page，再更新 mapping table

Answer

SSD 不會在原實體位置覆寫資料，而是將新資料寫入新的空白 Page，並將舊 Page 標記為失效 (Invalid)。

Key Concept

Erase-before-write (寫入前抹除) / Invalid Page

Detail

NAND Flash 必須先「抹除 (Erase)」才能「寫入 (Program)」，且抹除單位 (Block) 遠大於寫入單位 (Page)。如果在原位覆寫，必須搬移整個 Block 的資料，速度極慢。因此，FTL 永遠把資料寫到下一個空白位置，再把 Mapping Table 的指標更新過去。

了解 page-level mapping 與 block-level mapping 的差異，以及它們在彈性與 SRAM 記憶體開銷之間的取捨

Answer

Page-level 效能極佳但極耗 SRAM 記憶體；Block-level 極省記憶體但隨機寫入效能極差。

Key Concept

Mapping Granularity (映射粒度) / Read-Modify-Write (讀改寫)

Detail

Page-level 讓每個 Page 獨立映射，SRAM 需求約佔 SSD 總容量的 0.1%（極其昂貴）。Block-level 則綁定整個 Block 的 offset，只需少量 SRAM，但如果只更新 4KB 資料，卻必須把幾 MB 的整個 Block 讀出來修改再重新寫入，產生災難性的效能瓶頸。

知道 DFTL 等混合式 mapping 方案如何在有限的 SRAM 資源下兼顧效能與記憶體使用量

Answer

將完整的 Page-level 映射表存放在便宜的 NAND 中，只在 SRAM 快取最常存取的條目 (CMT)。

Key Concept

Demand Paging / Cached Mapping Table (CMT) / Locality (局部性)

Detail

借鑑作業系統虛擬記憶體的概念。大部分的工作負載都有局部性（只頻繁存取某些區塊），因此只要 SRAM 快取夠準確，就能用極小的記憶體成本，達到逼近純 Page-level 的超高效能。

一顆 2 TB SSD，page size 為 16 KB。如果採用 page-level mapping 且每個 entry 佔 4 bytes，mapping table 需要多少 SRAM？如果改用 block-level mapping（每個 block 有 512 個 page），又需要多少？

Answer

Page-level 需要 512 MB；Block-level 需要 1 MB

Key Concept

Mapping Table Size Calculation

Detail

Page-level：

總 Page 數 = 2 TB / 16 KB = 128,000,000 (128M)個。
每個 entry 4 bytes → 128M × 4 bytes = 512 MB。

Block-level：

總 Block 數 = 128M / 512 = 250,000 (250K) 個。
250K × 4 bytes ~ 1 MB。

為什麼 out-of-place write 讓 SSD 的 random write 在物理層面變成 sequential write？這個特性對 SSD 與 HDD 的效能差距有什麼影響？

Answer

因為不管主機給的 LBA 多麼隨機，FTL 都是將資料循序填入 NAND 中下一個連續的空白實體 Page。

Key Concept

Physical Sequential Write / 物理尋軌延遲

Detail

在 HDD 中，隨機寫入會導致磁頭在碟片上瘋狂移動（Seek time），耗時極長。但 SSD 透過 Out-of-place write，在底層一律轉換為「循序寫入」空白區塊。這是 SSD 隨機寫入效能能徹底輾壓 HDD 的根本原因。

DFTL 的 CMT miss 會導致什麼額外開銷？在什麼樣的 workload pattern 下，DFTL 的效能會明顯退化？

Answer

需額外去 NAND 讀取映射表，若替換的條目是髒資料 (Dirty) 還需寫入 NAND。在完全隨機 (Uniform Random) 的 Workload 下效能會嚴重退化。

Key Concept

Translation Page overhead / Cache Thrashing

Detail

CMT miss 時，SSD 必須暫停實際的資料讀寫，先去 Flash 把缺失的 Mapping entry 抓出來（NAND Read）；如果 SRAM 滿了要淘汰被改過的舊 entry，還要先寫回 Flash（NAND Write）。缺乏局部性的隨機存取會導致頻繁 Miss，讓延遲暴增。

假設一個混合式 FTL 使用 log block 方案，當 log block 滿了需要與 data block merge 時，最壞情況下需要多少次 NAND flash 讀寫操作？請用具體的 block/page 數量來說明。

Answer

最壞情況是 Full Merge，需要讀取與寫入各 N 次 (假設有 N 個 Page)

Key Concept

Full Merge / Write Amplification

Detail

最壞情況下，Log block 裡面的 N 個 Page 剛好分屬於 N 個不同的 Data block。這代表 FTL 必須針對這 N 個 Data block 各自執行一次 Read-Modify-Write：把舊 Block 沒更新的資料讀出來、合上 Log block 的單一 Page，再寫入新 Block。開銷極大。

如果 SSD 沒有 power-loss protection，突然斷電後重新開機時會發生什麼事？FTL 如何恢復 mapping table 的一致性？

Answer

SRAM 中尚未寫入 NAND 的 Mapping data 會遺失。重啟時需透過掃描 Flash 的日誌 (Log) 或 OOB 區域來重建映射表。

Key Concept

Dirty Entry Loss / Table Reconstruction

Detail

如果沒有電容撐住最後幾毫秒把 SRAM 寫回，最新寫入的資料雖然物理上存在 Flash 裡，但 FTL 「忘記」在哪了。開機時，控制器必須緩慢地掃描每個實體 Page 後方的 Out-of-Band (OOB) 區域（裡面會備註該 Page 屬於哪個 LBA），一塊一塊把 Mapping table 拼湊回來。

    (2) NVMe 的 HMB 技術確實是利用主機端記憶體，但其設計目的是為了存放 Mapping Table (Metadata) 設計的，而非用於快取 User Data。

  1. 一個 SSD 使用 DFTL。mapping table 的完整版本存放在 NAND flash 中，而 SRAM 中只存放一部分 mapping entries 作為 Cached Mapping Table (CMT) 假設 workload 為 uniform random write across the entire SSD，以下哪個現象最可能發生？
    1. CMT miss 只會增加 NAND read，不會增加 NAND write
    1. CMT eviction 可能導致額外 NAND write amplification
    1. CMT eviction 只會在 sequential workload 發生
    1. CMT eviction 不會影響效能，因為 mapping entry 很小
    Answer

    CMT eviction 可能導致 額外 NAND write amplification

    解析:

    在 uniform random write workload 下，大量不同的 LBA 會被更新，導致 CMT 不斷發生 miss 和 eviction。當被淘汰的 mapping entry 是 dirty entry 時，FTL 需要將修改過的 translation page 寫回 NAND flash，因此會產生額外的 NAND write。這種 translation page write 會增加整體 write amplification。

    (4) mapping entry 雖然很小，但 translation page 的寫入單位是 NAND page，例如 4 KB 或 8 KB。當一個 entry 被修改時，整個 translation page 可能需要重新寫入 NAND flash，因此 eviction 仍然可能帶來顯著的寫入成本。

    (3) CMT eviction 的發生與 workload 的 access locality 有關，而不是只會在 sequential workload 發生。實際上在 sequential workload 中，由於 locality 較好，CMT eviction 反而較少。

    (1) DFTL 在 CMT miss 時確實會產生額外的 translation page read，但 eviction 時如果 mapping entry 是 dirty，FTL 必須將對應的 translation page 寫回 NAND flash。由於 translation page 的寫入粒度是整個 page，而不是單一 entry，因此即使只有一個 mapping entry 被修改，也可能導致整個 translation page 被重新寫入，這會增加 NAND write 次數。

  1. 在資料庫索引中，更新一筆用戶紀錄通常只需要修改一個 4KB 的資料片段。假設我們將這個 4KB 的更新指令，送給一顆為了極致省成本而採用純 Block-level mapping（假設其實體 Block 大小為 4MB）的舊式 SSD。

    由於 NAND flash 存在「寫入前必須抹除 (Erase-before-write)」的物理限制，SSD 控制器為了解決這個 4KB 的更新，在底層確切會執行什麼樣的物理懲罰操作？為什麼這種架構會在現代高效能 SSD 中被淘汰？

    1. 控制器會將這 4KB 的新資料寫入一個全新的空白 Physical page，並單獨在 SRAM 中更新該 Page 的路由條目，同時將舊的 Page 標記為 Invalid，等待未來的 garbage collection 回收。
    1. 控制器會透過施加更高的編程電壓 (Programming voltage)，直接在該 4KB Page 目前的實體位置上進行強制覆寫 (In-place overwrite)，代價是會加速消耗該 Cell 的 P/E cycle 壽命。
    1. 控制器會將這 4KB 的更新暫存在 SSD 的斷電保護電容 (Capacitor) 中，直到累積滿 4MB 形成一個完整的 Block 後才一次寫入 Flash，這雖然避免了寫入放大，但會導致嚴重的寫入延遲。
    1. 控制器必須將舊 Block 中剩餘的有效資料全部讀入 RAM，將這 4KB 的新資料合併進去後，再將完整的 4MB 資料寫入到一個全新且已抹除的 Physical block 中。這個 Read-Modify-Write 過程會引發極度嚴重的 write amplification (寫入放大)。
    Answer

    控制器必須將舊 Block 中剩餘的有效資料全部讀入 RAM，將這 4KB 的新資料合併進去後，再將完整的 4MB 資料寫入到一個全新且已抹除的 Physical block 中。這個 Read-Modify-Write 過程會引發極度嚴重的 write amplification (寫入放大)。

    解析:

    這是正確的。根據講義，在純 Block-level mapping 中，對照表的粒度只到 4MB 的 Block。如果你只更新其中一個 4KB Page，FTL 無法像 Page-level mapping 那樣隨便找個新 Page 寫入並更新指標。它必須將整個 4MB 區塊的有效資料讀出來，在記憶體中替換掉那 4KB，然後重新寫入一個完整的 4MB 新區塊。這種災難性的 Read-Modify-Write 開銷是 Block-level mapping 被淘汰的主因。

    (3) 這代表對 SSD 硬體元件的嚴重誤解。斷電保護電容 (Capacitor) 是用來儲存「電能」的，目的是在突然斷電時提供緊急電力讓 SRAM 的資料寫入 Flash 中。電容絕對不是用來儲存或暫存「資料」的緩衝區。

    (1) 這個選項完美描述了 Page-level mapping 的運作方式（Out-of-place write），而非 Block-level mapping。純 Block-level mapping 沒有記錄單一 Page 位置的能力，因此無法做到這麼細粒度的靈活跳轉。

    (2) 這嚴重違反了 NAND Flash 最根本的物理定律。NAND flash 無論施加多大的電壓，都絕對無法進行 In-place overwrite（因為電子只能加不能減）。要清除資料，唯一的方法就是以龐大的 Block 為單位執行 Erase 操作。

  1. 現今的 SSD 大多採用 DFTL 或混合式 mapping 來管理 Flash 的 mapping table，請問下列關於這些 FTL 的敘述何者正確？
    1. CMT 不會定期將資料寫回 Flash 中，因為其中的資料不會揮發
    1. FTL 採用 out-of-place write，當發生 random write 時，舊的 physical page 會被標記為 invalid，而新資料則會配置到新的 free page，並以 sequential 方式寫入 SSD
    1. DFTL 的演算法中，在滿的時候通常會利用 LRU 來淘汰 CMT 裡的資料，是基於 Spatial Locality
    1. 除了 DFTL 的演算法外，Log block 的方法能徹底消除 Block-level mapping 在小資料更新中，所需要的 Read-Modify-Write
    Answer

    FTL 採用 out-of-place write，當發生 random write 時，舊的 physical page 會被標記為 invalid，而新資料則會配置到新的 free page，並以 sequential 方式寫入 SSD

    解析:

    SSD 不能進行覆寫，所以會將原本的 physical page 標記為 invalid，並將新資料連續地寫入空白的 Page，所以 SSD 的 random write 效能很高。

    (1) CMT 中的 SRAM 屬於揮發性記憶體，斷電後資料會遺失，因此需要定期將 Mapping table 寫回 Flash 中，以確保資料的持久性。

    (3) LRU 是基於 temporal locality，認為最近被訪問的資料在未來也很可能會被訪問，而不是 Spatial Locality。

    (4) Log block 只能起到緩衝的作用，最後還是需要將資料寫回原本的 block，因此仍然會有 Read-Modify-Write 的問題。

  1. 在一個採用 Fully-associative log-block 方案的混合式 FTL 中，假設一個 block 的大小為 N 個 pages。系統目前僅使用一個 log block 來處理寫入，且該 log block 已滿（內含 N 個 valid pages）。請考慮以下兩種極端場景，且兩者最終都必須透過 Full Merge 來清空該 log block：

    場景甲：該 log block 內 N 個 valid pages 的 LBA 均不重複，且完整覆蓋了「同一個」data block 的所有 LBA。

    場景乙：該 log block 內 N 個 valid pages 分別屬於 N 個「不同的」data block，且每個 data block 均僅有 1 個 page 被更新。

    若要將資料完全整理好並釋放空間，則關於這兩個場景的 NAND flash 讀寫與抹除（erase）次數消耗，下列敘述何者正確？

    1. 場景乙的 page 讀寫次數為場景甲的 N 倍，且需要抹除 N+1 個 blocks。
    1. 場景甲的 page 讀寫開銷會達到 NimesN 次，因為它必須把整個 NAND flash 晶片中所有無效的 pages 全部重新掃描一遍。
    1. 場景甲與場景乙造成的系統延遲與 write amplification 完全相同，因為兩者都是在回收一個滿的 log block。
    1. 場景乙可以透過 switch merge 直接取代舊資料，因此只需要執行 0 次 page 讀取與 1 次 block 抹除。
    Answer

    場景乙的 page 讀寫次數為場景甲的N倍，且需要抹除N+1 個 blocks。

    解析:

    場景甲只需對單一 data block 進行一次 full merge，代價為N次 page 讀取與N次 page 寫入。 而在場景乙中，由於N個 pages 散落在N個不同的 data block，且每個 block 都只有1 個 page 在 log block 中，FTL 必須針對這N個 data blocks 各別執行一次 full merge（讀取該 block 原本的N−1 個舊 page 加上 log block 中1 個新 page，再寫入新 block）。 這導致總讀寫次數膨脹為N×N次（即場景甲的N倍），並需要抹除N個舊 data blocks 與1 個 log block，總計N+1 次。

    (2) 在場景甲中，所有的變更都收斂在同一個 data block 內。FTL 只需要讀取該特定 block 的舊資料與該 log block 的新資料進行合併即可，不需要掃描整個晶片。

    (3) 這個選項忽略了 log block 的 associativity。當 log block 內的資料散落在不同 data blocks 時，FTL 無法在單次操作中完成重組，必須觸發多次獨立的合併流程，導致系統開銷成倍數暴增。

    (4) Switch merge 只能發生在 log block 內的資料與原本的 data block 完全一致（同一個 block 且順序相同）的情況下。場景乙的資料分散在多個不同的 blocks 且題目已限制必須執行 full merge，因此絕對無法使用 switch merge。

  1. In the DFTL architecture of an enterprise-grade SSD equipped with Power-Loss Protection (PLP), a Cached Mapping Table (CMT) is maintained in SRAM. When an unexpected power loss occurs, how does the SSD controller handle the "dirty" mapping entries in SRAM (entries that have been updated but not yet written back to NAND Flash) to ensure the SSD does not lose the locations of newly written data upon the next boot?
    1. It relies on a large power-loss protection (PLP) capacitor on the SSD circuit board to provide temporary power, giving the controller enough time to flush the dirty mapping entries from SRAM to NAND Flash.
    1. The SSD forces a synchronous out-of-place write to the Flash every time a mapping entry is updated in SRAM, so no extra handling is needed during power loss.
    1. It primarily relies on the OS file system's journaling mechanism. After a reboot, the journal is replayed to restore the underlying FTL's mapping state.
    1. Because a dirty entry represents obsolete data ready to be garbage-collected, losing it during a power loss will not corrupt the data, thus requiring no special protection.
    Answer

    It relies on a large power-loss protection (PLP) capacitor on the SSD circuit board to provide temporary power, giving the controller enough time to flush the dirty mapping entries from SRAM to NAND Flash.

    解析:

    This is a standard practice for enterprise or high-end SSDs. The large capacitor provides crucial milliseconds to seconds of power, ensuring that critical volatile data (including user data and the mapping table) safely lands in the non-volatile Flash.

    (2) If every modification required a synchronous write to Flash, it would cause extreme write latency and write amplification, completely defeating the performance purpose of caching the Mapping Table in SRAM.

    (3) OS journaling ensures file system consistency, but the OS is unaware of the underlying FTL's LBA-to-PBA mapping. The FTL's persistence must be handled independently by the SSD controller.

    (4) This is conceptually backward. A dirty entry represents the newest LBA-to-PBA mapping. If this information is lost, the SSD will not be able to locate the user's most recently written data, leading to severe data loss.

    1. 無法進行 merge，因為 log block 必須依照寫入順序與 data block 完全一致才能處理。

    (2) switch merge 的關鍵在於 logical coverage（是否完整覆蓋）， 而非實體寫入順序是否與原 data block 相同。

    (4) partial merge 適用於 log block 僅覆蓋部分 pages 的情況。 本題中 LB0 已完整覆蓋所有 pages，因此不需要 partial merge。
